# GPU 重建接入验证（2026-10-02）

硬件为 RTX 5060 Laptop，8,151 MiB，计算能力 12.0，驱动 595.91.07。
用户在 Ubuntu 24.04 编译 COLMAP 4.2.1，提交 bd1fcf6，CUDA 12.8.93，架构 120。
构建启用 CUDA，关闭 GUI、ONNX、CGAL、MVS、Caspar；当前流水线不依赖这些模块。

## 接入

`start-gpu.sh` 启动 8850 端口，隔离使用 `data-gpu/` 与 `work-gpu/`。
原启动方式及 CPU 引擎不变。支持通过 `SPLAT_COLMAP_REAL` 更换新引擎路径。
显式 GPU 模式只支持能独立识别的单张 NVIDIA 显卡；检测失败时给出错误。
使用原启动方式可以回到 CPU 流程，本轮未增加运行失败后自动 CPU 重试。

适配器处理 `SiftExtraction` / `SiftMatching` 到 4.x 通用参数的映射，保持
SIFT 专有参数不变；外部 COLMAP 不继承旧二进制的专用 LD_LIBRARY_PATH。
上游 OOOSplat 的 Linux CUDA 运行时检测仍会报告 CPU，因此通过显式适配器
请求 GPU，并从实际子进程初始化日志记录 `gpuConfirmed`。健康接口的
`colmapRuntime.gpuRequested` 只是配置意图，不是执行证据。

当前 GPU 加速特征提取和匹配；Mapper 仍采用原 CPU 优化。匹配线程数也控制
CPU 几何验证的并行度，不能为限制 GPU 工作者而把所有验证锁成一个线程。
GPU 模式的提取使用一个线程，匹配采用最多八个 CPU 验证线程。

## 验证与限制

用户手工测试的 64 帧顺序匹配：GPU 提取约 1.2 秒，GPU 匹配约 9.5 秒。
Mapper 输出两个分离模型，各 19 张图；模型 0 有 7,690 点，误差 0.754688px。
两个模型的图片没有交集，共涉及 38 张不同图片，但没有形成一个连续模型。
不能将两个子模型的图片数量相加当作完整、连续的场景覆盖。

适配器端到端短测试：同样 64 张图片，以图片集模式进行穷举匹配，显式将
训练缩为 1,500 步。注册 42/64（65.625%），7,886 稀疏点，导出 21,859 个
高斯，PLY 为 5,160,274 字节，总时长 105.420 秒。GPU 提取和穷举匹配均
观察到 SIFT GPU 初始化，返回码为零；训练前镜头校正完成。

该短测试的匹配阶段最初使用一个几何验证线程，耗时 58.461 秒，因此随后
调整为最多八个 CPU 验证线程，并在独立数据库上重新验证顺序匹配。
顺序匹配重新测试成功，耗时 6.394 秒，观察到 GPU 初始化，退出码为零。
41 项回归测试通过；独立目录的 GPU 网页入口健康检查通过，临时测试服务已关闭。
端到端原始日志为 `gpu-build/pipeline-smoke.log`，运行报告保存在
`gpu-build/pipeline-smoke/20261002-032835_frames/logs/`。

图片集穷举匹配与视频顺序匹配不是同一实验；此处只确认兼容性和真实 GPU
使用，不能据此宣称画质改善或完整视频的固定加速倍数。正式精细档仍为
30,000 步，尚未完成与旧引擎相同条件下的完整画质对照。
